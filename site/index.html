Record a task once.
Replay it with semantic steps, not pixel coordinates.

ReplayPilot is a Windows desktop agent. It watches what you do, stores the steps by name and role in the accessibility tree, and replays them even after the window has moved. It runs on local models. Nothing leaves your machine.

How it works

Three ideas, no screen-scraping, no coordinate guessing.

1 · Record

Show the tool what to do once. Steps are stored as semantic actions — focus_window, click_element, type — with the element's accessibility name and role, not the pixel it happened to be at.

2 · Store

Workflows are plain JSON on disk. Readable, diffable, editable by hand. No proprietary format, no cloud sync.

3 · Replay

At replay time the steps are resolved against the live accessibility tree. Move the window, resize it, change the layout — the button is found by name, not by memory of where it was.

Why these checks count as evidence rather than a self-report:

Verified by the app, not the agent

The target application writes its own state file. Verification reads the app's view. A replay that typed into the wrong place cannot satisfy it.

Corroborated by a second log

The app also writes an event log, and the harness requires it to agree independently with the recorded workflow.

Repeatable

The field is reset to a provably empty state and the replay is run a second time from scratch.

What does not work yet, stated plainly: full autonomous Execute mode needs one local model that both accepts images and emits tool calls. On this hardware no single small model does both, so Execute currently runs with a tool-capable model in accessibility mode, and vision runs in Answer/Teach with a separate vision model. This limit is documented, not hidden.

Privacy and safety

The tool drives a real mouse and keyboard, so the safety story is part of the product.

Loopback only

Model requests go to http://localhost:11434/v1. Verified by taking a TCP-connection snapshot before and after a full run: no new remote endpoint appeared.

Fail-closed focus guard

Every keystroke and click is bracketed by an identity check bound to the window's HWND and process. If the expected window is not in front, the run stops. There is no fallback to "whatever is active".

Games and credentials are blocked

Denylists are keyed on process name as well as window title, so a renamed or titleless game window is still refused.

Emergency stop

A kill-switch hotkey, plus a failsafe: slam the pointer into the top-left screen corner and automation aborts immediately.
